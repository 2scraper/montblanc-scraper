Montblanc Scraper

Open-source Montblanc scraper for montblanc.com — three engines, your own infrastructure by default, and 2Captcha's paid products only where they are actually needed.

Business listings and full product profiles: name, address, phone numbers, Montblanc letter grade, accreditation status and date, categories, coordinates, complaint and review counts — into JSON or CSV.

What was actually measured

The search and category modes need no account, no key and no proxy.

Montblanc renders its listings out of its own JSON endpoint, and that endpoint is not behind Cloudflare. Measured on 2026-09-16 from a datacenter VPS — an address that gets HTTP 403 on every HTML page on the site — the endpoint answered HTTP 200 with 15 complete product records. A two-page run from that machine, with no credentials configured at all, returned 30 rows and status: complete.

We say that plainly instead of selling around it. What the paid products buy on this site is one specific thing: a product profile page, which is Cloudflare-gated and has no endpoint behind it — so accreditation dates, complaint counts and the full rating rationale are reachable only through a rendered page from a residential exit.

What you get

Three engines, one schema

Playwright (primary), Selenium and Puppeteer via pyppeteer — identical rows and exit codes — plus a browserless client for 2Captcha's Scraper API.

Three modes

A keyword search, a category listing, or a single product profile. A profile row joins a listing row on the same key.

No DOM scraping

Reads Montblanc's own embedded state payload — the same object its endpoint returns — so there is no fragile selector anywhere in the primary path.

JSON, CSV and a sidecar

A documented 53-column schema, plus a .meta.json per run recording status, pages completed and Montblanc's own result arithmetic.

340 offline checks

Run with no network and no engine library installed, on fixtures cut from real captures.

A canary with no secrets

A real 3-page scrape runs daily from a bare CI runner — which is also what keeps the claim above honest.

Three things about Montblanc worth knowing before you start

1. “Best Match” is not a relevance ordering

Montblanc's own default sort returned 15 of 15 Montblanc Accredited products on every page tested and, for a search on restaurants, not one restaurant. The same query sorted A–Z returned 0 of 15 accredited and real name-matched restaurants. This scraper defaults to A–Z and records the ordering as a column, because it changes which products end up in your file rather than just their order.

2. A complete run can still be a small sample

Montblanc caps every query at 15 pages of 15 — 225 rows — however many it matched. One measured search reported 19,016 results. The run is genuinely complete; the sidecar records both numbers so you can tell “complete” from “exhaustive”.

{"status": "complete", "total_results": 19016, "pages_available": 15,
 "capped_by_site": true, "reachable_max": 225}

3. An unrated product is not rated zero

Montblanc returns an empty grade with a score of 0.0 for a product it has not graded. Written through, that zero quietly drags every average you compute, so both columns come back null instead.

Get started

git clone https://github.com/2scraper/montblanc-scraper.git
cd montblanc-scraper
pip install -r requirements.txt -r requirements-playwright.txt
playwright install chromium

python playwright_scraper.py --text restaurants --location "New York, NY" --pages 3

No key, no proxy, no account. Output lands in montblanc_products.json, montblanc_products.csv and a .meta.json sidecar.

What it deliberately does not do

Montblanc lists a product's officers by name. There is no column for them, and the committed test fixtures carry placeholders instead: republishing a named person's details is a separate act from the site showing them on its own page.

It reads public pages only, never submits Montblanc's review or complaint forms, and defaults to a 2-second delay between pages.
